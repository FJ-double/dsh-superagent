# 部署说明书（给执行部署的代理）

> 目标：在 **HP（Windows + Docker Desktop）** 上把内容生产工作台的 WebUI 跑起来，
> 局域网内手机/电脑都能打开。**只做部署，不改代码。**

## 一、材料

| 项 | 值 |
|---|---|
| 仓库 | `https://github.com/FJ-double/dsh-superagent.git` |
| 分支 | `agent/extract-article-design-903b08e5cb03` |
| PR | `https://github.com/FJ-double/dsh-superagent/pull/4` |
| 部署目录 | `%USERPROFILE%\workbench`（可改） |
| 端口 | `8787` |
| 项目性质 | 纯 Python 标准库，**无第三方依赖**，不需要 pip/venv |

## 二、前置检查（缺一个就先解决，别硬上）

1. `docker version` 能返回 Server 版本（Docker Desktop 已启动，托盘图标变绿）；
2. `docker compose version` 可用（v2，命令是 `docker compose` 不是 `docker-compose`）；
3. 8787 端口没被占用：`Test-NetConnection -ComputerName 127.0.0.1 -Port 8787`；
4. （可选，可后补）Obsidian 已装 **Local REST API** 插件并 Enable，端口 **27124**；
   没开也能部署，只是"取材"能力会显示不可用——**不要因此判定部署失败**。

## 三、部署（一条命令）

PowerShell（**不是** WSL、不是管理员才行的 cmd）：

```powershell
powershell -ExecutionPolicy Bypass -File $HOME\workbench\deploy\deploy-windows.ps1
```

若还没取代码，先：

```powershell
git clone -b agent/extract-article-design-903b08e5cb03 https://github.com/FJ-double/dsh-superagent.git $HOME\workbench
```

没有 git 时用 zip：

```powershell
$z="$env:TEMP\wb.zip"; iwr "https://github.com/FJ-double/dsh-superagent/archive/refs/heads/agent/extract-article-design-903b08e5cb03.zip" -OutFile $z
Expand-Archive $z "$env:TEMP\wbx" -Force
Move-Item "$env:TEMP\wbx\dsh-superagent-agent-extract-article-design-903b08e5cb03" "$HOME\workbench"
powershell -ExecutionPolicy Bypass -File $HOME\workbench\deploy\deploy-windows.ps1
```

脚本是**幂等**的：重复执行安全，已存在的 `deploy\.env` 不会被覆盖。

想一步到位（Obsidian 插件已开）就加参数：

```powershell
powershell -ExecutionPolicy Bypass -File $HOME\workbench\deploy\deploy-windows.ps1 -VaultToken "Obsidian 插件里的 token"
```

## 四、验收（五条全过才算装好）

| # | 检查 | 命令 | 通过标准 |
|---|---|---|---|
| 1 | 容器在跑 | `docker ps --filter name=workbench` | 状态 `Up`，端口 `0.0.0.0:8787->8787/tcp` |
| 2 | 页面可达 | `(iwr http://127.0.0.1:8787/).StatusCode` | `200` |
| 3 | 接口要口令 | `iwr http://127.0.0.1:8787/api/status` | 抛 401（说明口令生效） |
| 4 | 带口令能取状态 | 见下方"回传材料"第 2 条 | 返回 JSON，含 `capabilities` |
| 5 | 数据能落地 | `docker exec workbench ls /app/.data` | 有 `artifacts`、`cards` 等目录 |

## 五、回传材料（缺一样我这边没法接着干）

1. `deploy\.env` 里的 **WB_WEB_TOKEN 值**（页面口令）；
2. 带口令取状态的结果：
   ```powershell
   $t = (Get-Content $HOME\workbench\deploy\.env | ? { $_ -like "WB_WEB_TOKEN=*" }) -replace "WB_WEB_TOKEN=",""
   iwr http://127.0.0.1:8787/api/status -Headers @{ "X-WB-Token" = $t } | % Content
   ```
3. 局域网地址：`ipconfig` 里那条 IPv4，形如 `http://192.168.x.x:8787/`；
4. `docker compose -f $HOME\workbench\deploy\docker-compose.yml logs --tail=50`；
5. 五条验收的通过情况（哪条不过、报什么错）。

**不要回传任何 Obsidian token 的明文**，除非部署时确实要用它。

## 六、常见失败与处理

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动即报"绑定到局域网地址必须先设口令" | `deploy\.env` 里 `WB_WEB_TOKEN` 为空 | 填一个随机串，再 `docker compose up -d` |
| 构建报找不到 `workbench/` | 不在仓库根目录里 build | compose 已用 `context: ..`，务必从 `deploy\` 目录执行 |
| 8787 被占用 | 别的进程占了 | 改 `deploy\docker-compose.yml` 的 `ports: "8788:8787"`，或停掉占用者 |
| 页面能开但"取材不可用" | Obsidian Local REST API 没开 | **不是故障**，属预期；开了插件后重启容器即可 |
| 容器内连不上 Obsidian | Windows 上不能用 `127.0.0.1` | 用 `https://host.docker.internal:27124`（脚本默认值），自签证书需 `WB_VAULT_VERIFY_TLS=false` |
| 局域网手机打不开 | Windows 防火墙拦截 | 只放行内网：`New-NetFirewallRule -DisplayName "workbench" -Direction Inbound -LocalPort 8787 -Protocol TCP -Action Allow -RemoteAddress LocalSubnet` |

## 七、边界（请严格遵守）

- **不改代码**。要改先提，由项目方改；
- 不把 `config.toml`、`.env`、任何 token 提交进 git；
- 不把 8787 暴露到公网，只放行局域网；
- 不动这台机器上与本项目无关的服务与配置。
