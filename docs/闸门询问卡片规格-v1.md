# 闸门询问卡片规格 v1（票拟式，同意 / 拒绝 / 自定义回复）

> 依据：2026-11-02 14:58 答复「2 改为卡片形式我赞同，给出你的建议询问卡片我来审批同意或拒绝，或者自定义回复」。
> 定位：替换 v0.3 的 `gate.request → 飞书卡片`。**卡片不再是一道选择题，而是一份"已经替你做完、请盖章"的票拟。**

## 1. 卡片骨架（9 个字段，全部有则必填）

| 位 | 字段 | 约束 | 为什么必须 |
|---|---|---|---|
| 1 | `ask` 一句话请示 | ≤30 字，必须含"我建议做什么" | 你 3 秒内要知道我在问什么，不要"请审阅"这种废话 |
| 2 | `recommendation` 我的建议 | `approve` / `reject` / `rerun` / `escalate` + 置信度（高/中/低） | 票拟的核心：**没有建议的卡片等于把决策推回给你** |
| 3 | `reasons[]` 为什么 | ≤3 条，每条必须带数字或证据引用 | 防止"我觉得挺好"式论证 |
| 4 | `metrics` 关键数字 | 质量分、事实可溯源率、成本（本条/今日累计/档位上限）、平台限额余量 | 你要能一眼算账 |
| 5 | `risk` 最坏情况 | 一句话最坏结果 + 一句话"我为什么不担心" | 报喜不报忧的卡片是无效卡片 |
| 6 | `done[]` / `todo[]` | 已跑的检查逐条列名；未做的逐条列原因 | 让你知道"兜住了什么、漏了什么" |
| 7 | `alternatives[]` | ≤2 条可执行替代（换标题/换角度/降级草稿/推迟） | 只在"A 或 B"里选，比开放提问省脑力 |
| 8 | `question` 唯一请示项 | 一个问题，不许多问 | 多问=让你重新做一遍工作 |
| 9 | `footer` | `run_id`、产物版本、卡片有效期、今天第几张 | 可追溯 + 你有权让卡片过期 |

## 2. 三个按钮的语义（含后果，必须写死）

| 按钮 | 行为 | 下游动作 | 沉淀 |
|---|---|---|---|
| **同意** | 执行卡片的 `recommendation` 对应路径 | 继续推进；卡片原地改写成"已批红 · 结论 · 时间" | 记 `approve`，不改偏好 |
| **拒绝** | 终止当前 run（不自动重试） | 产物转为 discard，写 `reason` | 记 `reject` + 原话，**默认勾选"记入长期偏好"**（可取消） |
| **自定义回复** | 自由文本 → 意图解析 → **回执二次确认** | 见 §3 | 记原文 + 解析结果 |

> 拒绝与同意都不需要你打理由；只有自定义回复需要打字——**默认路径零输入**。

## 3. 自定义回复的解析规则（不做"猜"，只做"确认"）

自由文本只归入三类，解析后**必须回显"我理解你要我做的是 X，对吗？[确认/不是]"**，确认后才执行：

| 意图 | 触发例子 | 系统动作 | 不改状态的情形 |
|---|---|---|---|
| `redirect` 改方向 | "换个角度""别写盘点""从小红书视角重写" | 写 `redirect_hint`，从受影响的最上游层局部重跑（`orch.run.replay`） | — |
| `tune` 改参数 | "标题改成…""封面用第 3 张""预算可以到 ¥5" | 改对应产物字段，只重跑该层及下游校验 | 参数越界（超预算/超平台限额）→ 回问一句 |
| `answer` 纯答复 | "用 A 方案""这个不用标来源" | 仅作为本次决策依据，回答后卡片重新挂起，等你批 | — |
| `unparsed` 解析不了 | 模糊、多问混答 | **不改任何状态**，回一句"我没懂，你要的是①改方向②改参数③只是答复？" | 全部 |

硬规则：**解析置信度低 → 一律走 `unparsed`，绝不擅自执行。**（宁可多问一轮，也不猜你的话）

## 4. 四类卡片的差异化

| 卡片 | 触发时机 | 卡片里必须额外带 | 默认建议怎么给 |
|---|---|---|---|
| **G1 选题请示** | L1 出 40 候选后 | 候选清单，其中**预勾选我推荐的 1–3 条**（不是让你从 3–8 里挑） | 按推荐开工 |
| **G2 文稿请示** | L3 成稿后 | thesis + 前 3 段 + 结构 + `fact_sheet.gaps`（想讲但没证据的点）+ `red_flags` | 进版式 |
| **G3 发布请示** | L6 质检后 | 封面 + 首屏 + 平台限额余量 + **AI 声明勾选状态** + 发布方式（auto / manual_fallback 打包） | 发布 |
| **异常请示** | 命中"不确定"清单（见 v0.5 §3） | 卡在哪一步 + 我试过什么 + 需要你定的点 | 按情形（可能是"暂停这条线"） |

## 5. 样例（G3）

```
小红书卡片组《我把 3 个 AI 工具当同事用了 7 天》已过质检，建议今晚 21:00 发

建议：发布（置信度 中高）
为什么：① 质检 86 分、无 critical ② 12 条断言全部命中仓库里的原始出处 ③ 同角度近 90 天未发过
关键数字：本条 ¥2.4 ／ 今日累计 ¥11.6（档位上限 ¥15）｜标题 18 字（限 20）｜9 张图（限 12）
风险：最坏情况是选题撞昨日竞品导致互动低；我不担心，因为角度是"7 天实测"不是"清单盘点"
已做：四类质检 · 事实校验 · 平台限额 · AI 声明已标注 · 元数据未剥离
未做：小红书无发布 API → 走 manual_fallback，给你打包 + 一键发清单
备选：A 换标题《…》重出（约 3 分钟）　B 降级为草稿，明天再看
请批：现在发，还是走备选 A？

[ 同意 ]   [ 拒绝 ]   [ 自定义回复 ]
run 4c1f… ｜ v1.3 ｜ 有效期 6 小时 ｜ 今日第 2 张
```

## 6. 与现有 schema 的关系（向后兼容）

- 保留 `gate.request / gate.decide / gate.timeout / gate.escalate` 四个接口，**不改签名**。
- `gate.request` 的 `payload_ref` 增加 `gate_card@1`（上面 9 个字段 + `alternatives`）；`gate.decide.decision` 枚举不变（`approve/reject/redirect`），`redirect` 承载自定义回复解析出的三类意图，解析原文进 `note`。
- 新增 `gate.decide.receipt`（回执）：`{parsed_intent, echo_text, confirmed:bool}`——**没有 `confirmed=true` 不得执行 redirect**。
- 审计：每张卡片的渲染快照、你点的时间、你打的原文全部落 `audit`，作为复盘材料（对应"减少信息不对称"这件事的原料）。
