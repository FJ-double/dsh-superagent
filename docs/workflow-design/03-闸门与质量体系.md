# 03 闸门与质量体系

> 本文件回答两个问题：**什么情况下机器放行、什么情况下必须人点头、以及"好"到底怎么量化。**
> 没有这一层，"全自动"等于"全自动产出垃圾"；闸门太密，则等于"人工流水线换了个壳"。

---

## 1. 三道闸门的设计原则

1. **闸门放在"方向错了会很贵"的位置**：选题（错了浪费整条产线）、脚本（错了浪费渲染）、成片（错了伤账号）。
2. **闸门判定必须可机器预判**：人只做"同意/否决/改方向"，不做逐字校对。机器先把不合格的挡在闸门外。
3. **闸门必须有 SLA 与超时策略**：否则系统卡在等人，产能不可预测。
4. **闸门可逐级放开**：同一账号跑够样本量、FPR 稳定后，从"人审"降级为"抽检"，最终"自动放行 + 事后抽检"。

| 闸门 | 位置 | 默认模式 | 人工动作 | SLA | 超时策略 |
|---|---|---|---|---|---|
| G1 选题批准 | L1 之后 | 人工批量（1 次点击/批） | 从 3–8 条候选中勾选 | 工作日 4h | 超时保持待审，不消耗下游预算 |
| G2 脚本批准 | L3 之后 | 人工（前 30 条 100%，之后抽检 20%） | 通读 + 通过/打回 | 8h | 超时自动通过仅当全绿且风险分低，否则挂起 |
| G3 发布批准 | L6 之后 | 人工（抽检 20% + 全部低分稿 + 首 10 条全审） | 看成片/成图 + 发布 | 4h | 超时**不自动发布**，顺延到下一时段 |

---

## 2. 闸门判定条件（机器预处理）

### G1 选题批准

**自动淘汰（不进闸门）**
- 命中禁用词表 ≥ 1 处；
- `counter_intuitive` 为空，或与已有发布内容同簇（相似度 > 0.86）且 90 天内发过；
- `risk_flags` 非空（医疗/金融/政治/未成年/商标/诽谤）；
- `evidence_seeds` < 3；
- `scores.total` < 3.2。

**自动推荐（排序进卡片）**
`rank = 0.6*scores.total + 0.3*history_similar_performance + 0.1*platform_trend_fit`

**人工看到什么**（飞书互动卡片，每条一行）
```
① [4.5] 为什么"越努力越穷"其实是个财务结构问题
   反直觉：勤奋不是变量，现金流结构才是
   证据种子：4 条 | 同类历史：+38% 完播 | 风险：无
   [✅ 通过] [⏭ 换一个] [❌ 否决（记原因）]
```
批次卡片底部：`[全部通过 Top3] [本轮全否决] [今天不发了]`。

**记录**：否决必须选原因（无趣/太窄/风险/重复/其他）→ 进 L1 权重与红队样本库。

### G2 脚本批准

**机器先跑（全绿才进人工；有 fail 直接回 L3 自修，不打扰人）**
| 项 | 条件 |
|---|---|
| schema | 通过 |
| 事实可溯源 | 断言命中 fact sheet 100% |
| 无源断言 | 0 处（`assertable=false` 未被当事实写） |
| 信息密度 | 每 100 字可断言事实 ≥ 1.2（长文）/ 2.0（口播） |
| 硬约束 | 每节数字/案例/反直觉/视觉锚点齐备 |
| 禁用词 | 0 处 |
| 预算偏差 | ≤ ±15% |
| critic | 全部段落 verdict=pass |

**人工看到什么**：稿子全文 + 左侧"事实标注"（每个数字/断言可点开看来来源）+ 密度热力图 + `[通过] [打回并说明] [改标题]`。

**抽检降级规则**：同账号连续 20 条 G2 人工"零修改通过" → 抽检比例降到 20%；出现 1 次严重问题 → 回到 100%。

### G3 发布批准

**机器先跑**：`qa_report.decision == pass`（见第 4 节），否则不出现。
**人工看到什么**：成片播放器/卡片预览 + QA 报告摘要（红色项高亮）+ 平台适配信息 + `[发布] [改一版] [弃稿]`。
**必须人审的情形**：账号首 10 条；`quality_score < 85`；含医疗/金融/法律相关表述；含真实人物/品牌；`compliance` 组出现 warn。

## 3. 人工复核的"内容好坏"rubric（仅在抽检时用，用于校准机器）

| 维度 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| 新颖度 | 全是你听过的 | 有一点新角度 | "我没想到" |
| 信息密度 | 正确的废话 | 有 1–2 个硬事实 | 每屏都有新信息 |
| 张力 | 平铺直叙 | 有一个转折 | 全程被推着看下去 |
| 视觉表达 | 图文堆砌 | 有设计感 | 抽象概念被画出来了 |
| 可信度 | 明显不可信 | 大体可信 | 敢给出处、敢给反例 |

抽检 ≥ 3 分视为"可发"；连续 20 条 ≥ 3.5 → 阈值可下调（自动化程度提高）。

## 4. 自动 QA：五组检查与阈值

> 全部可机器判定。**critical 项一票否决**，其余加权计分，`score ≥ 80` 放行。
> 阈值表有版本号（`thresholds@2026.11.1`），改动走 ADR 并跑回归集。

### 组 1 结构（权重 10%）
| 项 | 阈值 | 级别 |
|---|---|---|
| JSON Schema 通过 | 100% | critical |
| 时长/字数在预算 ±15% | 是 | major |
| 章节完整性（outline 每节都有正文） | 100% | critical |
| 首帧/首卡存在钩子文案 | 是 | major |

### 组 2 事实（权重 25%）
| 项 | 阈值 | 级别 |
|---|---|---|
| 断言 → fact sheet 命中率 | = 100% | critical |
| 数字与来源值一致（容差 0） | 100% | critical |
| 来源链接存活 | ≥ 98% | major |
| 独立来源数 | ≥ 3 | major |
| 反例覆盖 | ≥ 1 | major |
| 过期事实（`valid_until` 已过）未标注时点 | 0 | major |

### 组 3 合规与平台（权重 25%）
| 项 | 阈值 | 级别 |
|---|---|---|
| 敏感词/违禁词 | 0 | critical |
| 绝对化用语（"最/第一/唯一/100%"） | 0（除引用且标注） | major |
| 医疗/金融/法律断言 | 0（除有资质来源且标注"非建议"） | critical |
| AI 生成内容标识 | 必须存在 | critical |
| 素材版权字段完整且未过期 | 100% | critical |
| 肖像/商标/他人作品出镜授权 | 100% 有记录 | critical |
| 标题党指数（标题与内容偏离度） | ≤ 0.3 | minor |
| 平台规范（时长/尺寸/字数/标签数） | 符合该平台配置 | critical |

### 组 4 技术（权重 20%，视频/图文适用）
| 项 | 阈值 | 级别 |
|---|---|---|
| 黑帧/纯色帧连续 | ≤ 0.2s | critical |
| 静音段（非设计停顿） | ≤ 0.5s | major |
| 字幕出框/被遮挡/断行错误 | 0 | critical |
| 音画同步偏差 | ≤ 80ms | critical |
| 分辨率/帧率/码率符合平台 | 符合 | critical |
| 响度 | -14 LUFS ±1；真峰值 ≤ -1 dBTP | major |
| 首帧吸引力（对比度/文字面积/人脸或主体） | 打分 ≥ 3/5 | minor |
| 图文：字号最小值/对比度 ≥ 4.5:1/边距安全区 | 符合 | major |

### 组 5 视觉丰富度（权重 20%，专拦"幻灯片"）
| 项 | 阈值 | 级别 |
|---|---|---|
| 最长静态连续时长 | ≤ 4.0s | critical |
| 视觉事件密度 | 15–40 次/分钟 | major |
| 任意时刻运动层数 | ≥ 2 层（≥ 80% 时长） | major |
| 镜头数/分钟 | ≥ 12（短视频）/ ≥ 8（长视频） | major |
| 景别多样性（熵） | ≥ 1.2 bit | minor |
| 同景别连续 | ≤ 2 次 | minor |
| 生成片段占比 | ≤ 20% 镜头数 | minor（成本护栏） |
| 画面重复（帧级相似） | 跨镜头相似度 ≤ 0.9 | major |

### 计分公式
```
score = 100 * Σ_g ( w_g * pass_ratio_g )
pass_ratio_g = 该组通过项权重和 / 该组项权重和（critical 项 fail ⇒ 整体 0 分）
decision = "pass" if score>=80 and no critical_fail else "retry"(route_back) | "discard"(attempt>=3)
```

## 5. 指标定义（口径统一，避免各说各话）

| 指标 | 公式 / 口径 |
|---|---|
| 一次通过率 FPR | 首次 `qa_report.decision=="pass"` 的 run 数 ÷ 提交 QA 的 run 数 |
| 人工分钟/条 | (G1+G2+G3 人工耗时 + 异常介入耗时) ÷ 发布条数 |
| 可溯源断言率 | 命中 fact sheet 的断言数 ÷ 全部断言数 |
| 信息密度 | 可断言事实条数 ÷ (字数/100) |
| 视觉事件密度 | `visual_events` 总数 ÷ 时长(分钟) |
| 静态连续时长 | 相邻视觉事件的最大间隔（无事件即算静态） |
| 单条全成本 | Σ(模型 + 渲染 + TTS + 存储摊销 + 素材摊销) ÷ 合格条数 |
| 弃稿率 | `decision=="discard"` 数 ÷ run 数 |
| 3s 留存 | 平台回采（T+24h） |
| 内容 ROI | (完播率提升 × 权重) ÷ 单条成本（内部排序用，非对外指标） |

## 6. 离线评测集（换模型、调阈值前必须跑）

| 集合 | 规模 | 用途 | 通过标准 |
|---|---|---|---|
| `eval_ideas` | 100 个历史题材 | 检验 L1 发散度与去重 | 簇中位数相似度 < 0.6；人工"没想到"率 ≥ 25% |
| `eval_facts` | 60 条已知真假混编断言 | 检验 L2 幻觉率 | 假断言判不可断言 ≥ 95%；真断言误杀 ≤ 10% |
| `eval_scripts` | 30 篇人工金标稿 | 检验 L3 密度与结构 | 密度 ≥ 金标 90%；结构分 ≥ 4/5 |
| `eval_qa` | 50 个已知问题样本（含黑帧/错字幕/无源断言/幻灯片） | 检验 L6 检出率 | 召回 ≥ 95%，误报 ≤ 5% |
| `eval_render` | 10 条基准 shot_list | 检验渲染一致性与缓存 | 两次渲染哈希一致；缓存命中后耗时 ≤ 20% |

**回归纪律**：任何 prompt/阈值/模型变更 → 跑全量评测集 → 与基线对比 → 退步则回滚。评测集本身版本化。

---

## 7. 实验与调优

- **A/B 对象**：标题、封面/首帧、开场 3 秒结构、节奏参数（事件密度）、时长（60s vs 90s）。
- **分流单位**：作品级（同一选题的双版本不同时发同一账号，避免流量互抢；用同账号不同日期或不同平台对照）。
- **判定**：以 3s 留存与完播率为主指标，最小样本 30 条/组，用贝叶斯或自助法给区间，不追单条显著性。
- **bandit**：对选题矩阵的组合做加权采样（Thompson sampling），探索比例初始 0.3，按月衰减。

---

## 8. 阈值治理

1. 阈值文件独立于代码（配置中心），有版本号、有变更记录、有回滚。
2. 每次变更记录：改了什么、为什么（误判样本）、影响评估（评测集 + 抽检结果）。
3. 每月复盘一次：弃稿原因分布、误判样本、人工改稿 diff（看人最常改什么 → 那就是机器最该学的地方）。
4. **禁止**为了"提高自动化率"而下调 critical 项阈值。
