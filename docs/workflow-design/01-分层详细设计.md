# 01 分层详细设计（L0–L7）

> 每层统一按七项描述：**职责 / 输入 / 输出 / 处理策略 / 关键参数 / 失败模式 / 本层验收**。
> 数据结构的字段定义见 `02-数据契约.md`；闸门判定见 `03-闸门与质量体系.md`。

全局约定：
- 所有阶段输入输出都包在统一信封 `StageResult` 中（含 `run_id / stage / inputs_hash / producer / payload`），保证可重入与可追溯。
- 所有模型调用都通过模型网关，**不得在业务代码里直连供应商**；提示词一律带 `prompt_id@version`。
- 所有阶段必须支持"给定输入即得同一输出"（temperature=0 或固定 seed；生成式图像/视频记录 seed）。

---

## L0 资产与基建：决定系统上限的一层

自动化系统之间的差距 90% 不在模型，而在这层。

### 职责
提供**可复用、可累积**的差异化资产 + 工程底座。L0 不产出内容，但决定内容的上限与成本曲线。

### 组成与规格

| 资产 | 内容 | 规格要求 |
|---|---|---|
| 选题/角度矩阵 | 受众 × 场景 × 冲突 × 反常规 × 形式 × 情绪 | 每维度 ≥ 6 个枚举值，可组合抽样；带历史表现权重 |
| 钩子库 | 前 3 秒/首句高完播句式与结构 | ≥ 100 条起，每条带：句式模板、示例、适配形态、来源作品与指标、适用禁区 |
| 事实源清单 | 行业报告、官方统计、论文、自有数据 | 每条带：可信等级（A/B/C）、更新频率、抓取方式、最近校验时间 |
| 风格系统 style token | 色板、LUT、字体栈与字阶、网格、图标集、图形语言、动效曲线、颗粒 | 一台机器可读的 JSON，视频/图文共用；带版本号 |
| 素材库 | BGM（BPM/情绪/版权）、音效、b-roll、图表模板、转场预设、背景纹理 | 素材元数据必须含版权字段与到期日；禁止无授权素材入库 |
| 模板库 | 图文排版模板、卡片版式模板、视频章节/结尾/下三分之一模板 | 参数化：只允许填内容，不允许改结构 |
| 模型网关 | 路由/重试/限流/缓存/计费/trace | 统一接口，按 `capability`（chat/embed/image/video/tts/asr）而非按厂商调用 |
| 编排底座 | 状态机 + 对象存储 + 元数据库 + 队列 | 支持人工等待、超时、重试、预算熔断 |

### 处理策略（资产如何"活起来"）
1. **冷启动**：用用户既有爆款样本反拆钩子与风格（输入 10–20 条样本即可起步）。
2. **持续积累**：L7 回采的高互动段落、L6 误判样本、L1 高完播选题自动回流到对应库，走"候选 → 人工确认 → 生效"流程，防止污染。
3. **版本治理**：style token、模板、钩子库都带 `version`，产物记录所用版本，出问题可回滚。

### 失败模式
- 资产缺失 → 模型只能凭训练分布发挥（就是现在的症状）；
- 资产无元数据（版权/来源/有效期）→ 后期合规灾难；
- 资产被自动回流污染却无人复核 → 质量缓慢劣化。

### 本层验收
- 每类资产有库、有 schema、有版本；
- 任一产物可回答"用了哪一版 style token / 哪几条钩子 / 哪批素材"；
- 素材 100% 带版权字段。

## L1 选题与角度：解决"思路展不开"

### 职责
把"今天发什么"变成**一批可评分、可去重、可溯源的候选选题**。

### 输入
`TopicRequest{content_type, audience_hint, platform, n_candidates, history_window_days, banned_topics, budget}` + L0 资产（矩阵、钩子库、历史选题）。

### 输出
`idea_batch`：20–60 条 `IdeaCard`（含评分与去重簇），其中 3–8 条进入闸门①。

### 处理策略（三路并行发散 + 强制收敛）

**A 检索驱动**（真实需求在评论区）
- 抓热点榜、搜索下拉词、同类高播放作品的**评论区高赞疑问**与"没被回答的问题"；
- 输出：`demand_seeds[]`（问题原句 + 出现频次 + 来源）。评论区往往比选题工具更准。

**B 结构化变异**（组合矩阵抽样）
- 矩阵：`受众(新手/进阶/决策者/旁观者) × 场景 × 冲突 × 反常识角度 × 形式(清单/对比/实验/复盘/辟谣/故事) × 情绪(焦虑/好奇/爽感/共鸣) × 时间尺度`；
- 抽样 30–60 组，**每组一次独立调用**（不是一次调用要 50 个想法），每次只产出一句话"核心张力"；
- 独立采样的意义：避免同一 prompt 内的模式坍缩。

**C 红队反陈词**（对"打开思路"提升最明显的一步）
- 先让模型列出"关于该主题，所有人都会说的 5 句话"；
- 生成候选后强制自检：与该陈词列表语义相似度 > 阈值即丢弃；
- 附加要求：`analogy_from_other_domain`（从另一个行业借结构解释本主题）。

**发散期硬约束（可机检）**
- 禁用词表（"赋能/底层逻辑/值得深思/在这个时代/众所周知"…）；
- 必须包含一个**反直觉点**：若"目标读者已经知道"，则丢弃；
- 必须给出 ≥ 3 条 `evidence_seeds`（L2 可执行的检索方向），否则视为空想；
- 多视角变体：外行 / 专家 / 反对者 / 利益受损者 各写一版再交叉。

**收敛**
1. 评分 rubric（1–5）：新颖度、可验证性、受众相关度、可视觉化程度、合规与品牌安全；
2. embedding 聚类去重（相似度 > 0.86 同簇），每簇只留总分最高者 —— 否则"50 个想法"其实是 8 个；
3. 与近 90 天已发内容比对（同簇直接淘汰，近簇需新角度）；
4. 加权排序：`final = 0.6*score_total + 0.4*历史同类表现分`（冷启动期权重衰减到 0）。

### 关键参数
| 参数 | 默认 | 说明 |
|---|---|---|
| `n_candidates` | 40 | 每批候选数 |
| `dedupe_sim_threshold` | 0.86 | 聚类合并阈值 |
| `min_evidence_seeds` | 3 | 每条 idea 最少检索方向 |
| `novelty_vs_history_days` | 90 | 重复窗口 |
| `batch_size_to_gate` | 5 | 进入人工审批的条数 |

### 失败模式
- 只给一个 prompt 要 50 个想法 → 50 个同义反复；
- 无红队 → 选题全是"正确但没人看"的命题；
- 无历史去重 → 反复发同一件事，账号被判低质。

### 本层验收
- 候选集内两两相似度分布中位数 < 0.6（说明真的发散了）；
- 100% 候选通过禁用词与"必须含反直觉点"检查；
- 每批至少 1 条候选在人工评审中被判"我没想到"（主观但有效的信号，作为评审期指标）。

## L2 研究取证：解决"内容不够"的根本

> **这是最重要、也最常被跳过的一层。没有新信息注入，模型输出的上限等于训练语料的平均值。**

### 职责
把 idea 变成**可引用、可断言、带冲突视角**的事实底座。

### 输入
`IdeaCard` + L0 事实源清单 + 检索工具集（web 搜索、站点抓取、报告库、站内知识库、视频转写）。

### 输出
`fact_sheet`：`claims[]`（每条含证据、来源、置信度、是否可断言、保守表述）+ `counter_evidence[]` + `open_questions[]`。

### 处理策略
1. **生成检索计划**：5–12 条**具体**查询，不是"讲讲 X"，而是"X 2024 年增长率 官方统计""X 失败案例 复盘"。
   查询类型配额：定义类 1、数据类 3、案例类 2、反例类 2、时间线 1、争议 1。
2. **多源抓取**：优先 A 级来源（官方统计/学术/一手财报），B 级（权威媒体/行业报告），C 级（自媒体，仅用于找线索不用于断言）。
3. **抽取六类素材**：数字、案例（有人/地名/时间）、引述、反例、时间线、争议点。**反例必采至少 1 条**——厚度来自张力，不来自字数。
4. **交叉校验**：同一 claim 若 ≥ 2 个独立来源一致 → `confidence=high`；单一来源 → `mid`；仅 C 级或自相矛盾 → `low` 且 `assertable=false`。
5. **降级规则（硬规则）**：`assertable=false` 的 claim 只能以观点句出现或删除；数字必须带单位、口径、时点。
6. **产出摘要卡**：`research_brief`（300 字内）供 L3 冷启动上下文，避免把全网原文塞进 prompt。

### 关键参数
| 参数 | 默认 | 说明 |
|---|---|---|
| `min_assertable_facts` | 8 | 长文 12；短视频 8 |
| `min_independent_sources` | 3 | 独立来源数 |
| `min_counter_evidence` | 1 | 反例下限 |
| `max_fetch_pages_per_claim` | 3 | 成本控制 |
| `source_recency_window` | 24 月 | 超期事实需标注时点 |

### 失败模式
- 直接跳过检索开写（最常见）→ 内容空、幻觉多；
- 只抓"支持自己观点"的证据 → 内容没有张力，且极易被打脸；
- 把 C 级自媒体当事实源 → 违规与事实错误；
- 来源不可达/付费墙 → 必须有降级路径（换角度或标注不可断言）。

### 本层验收
- `assertable=true` 的 claim ≥ 门槛，独立来源 ≥ 3，反例 ≥ 1；
- 每条 claim 有 URL/文档 ID 与抓取时间戳；
- 后续成稿断言可 100% 回溯（在 L6 校验）。

## L3 大纲与脚本：用"信息密度契约"替代"写得丰满点"

### 职责
把事实组织成**有张力、有节奏、可机器校验**的稿件（视频形态下同时产出配音稿）。

### 输入
`fact_sheet` + `research_brief` + `content_type` + 目标时长/字数 + 平台规范 + 风格 token。

### 输出
- `outline`：章节 → 每章主张 → 绑定的 claim id → 情绪曲线位置 → 配额（字数/秒）；
- `script`：逐节成稿（`sections[]`），视频形态附 `vo_text`（口播稿）与 `on_screen_text`（屏幕字）。

### 处理策略（两段式，绝不一次成稿）

**第一段：大纲**
- 结构模板可选：`问题-误解-真相-证据-方法-反例-行动`、`清单式`、`对比式`、`复盘式`、`辟谣式`；
- 每个章节必须绑定 ≥ 1 条 `assertable=true` 的 claim id（绑不上 → 该章节删除，这叫"证据驱动删节"）；
- 检查"so what 链"：每章是否推进论点，还是原地打转（用 critic 判定，打回重排）；
- 情绪/节奏曲线：开场钩子 → 第一个反转（前 15%）→ 证据堆叠 → 高潮案例 → 收束行动。

**第二段：逐节扩写**
- 每次只写一节，输入 = 本节要素 + 绑定的 facts + 上一节末句 + 下一节首句（衔接约束）；
- 好处：可并发、可单节重写、上下文不漂移。

**每节的硬约束（全部可机器校验）**
| 约束 | 判定方式 |
|---|---|
| ≥1 个具体数字或时间点，且与 fact sheet 一致 | 正则抽数字 + 与 claim 比对 |
| ≥1 个具体案例（有人/地名/时间三要素之一以上） | NER + 规则 |
| ≥1 个反直觉点或反例 | 段落级判定 + 人工抽检 |
| ≥1 个"可视觉化锚点"（能画出来的对比/流程/数字） | 抽取 `visual_anchor[]` 字段（供 L4） |
| 禁止段首空转句（"随着…的发展""众所周知"） | 黑名单正则 |
| 每 3 句内出现新信息 | 相邻句 embedding 相似度 < 阈值 |
| 字数/时长在预算 ±15% | 计数 |

**critic 收敛**
- 评审模型逐段三项判定：有信息增量？可被证伪？读者视角值得读？
- 不通过打回，**最多 3 轮**，超限降级为"删除该段"（宁可短，不要水）；
- 评审意见必须结构化（问题类型 + 定位 + 建议），便于自动化重写而不重写全篇。

**视频形态额外规则**
- 口播稿按"呼吸单元"分段（每段 1–2 句，15–25 字/句），便于 TTS 与字幕；
- 每 20–30 秒设一个"再钩子"（re-hook）；
- 屏幕字与口播字**不重复**（字幕之外的屏幕字只放关键词/数字）。

### 关键参数
| 参数 | 默认 |
|---|---|
| `critic_max_rounds` | 3 |
| `budget_tolerance` | ±15% |
| `min_facts_per_section` | 2 |
| `max_sentence_len` | 45 字（视频口播 25 字） |
| `rehook_interval_sec` | 25 |

### 失败模式
- 一次成稿 → 上下文互相污染、无法定位问题、改一处全崩；
- 只追求"流畅"不追求信息 → 正确的废话；
- 章节与证据脱钩 → 出现无源断言（L6 会拦，但浪费一次渲染）。

### 本层验收
- 每节硬约束 100% 通过；
- 成稿断言 → fact sheet 命中率 100%（L6 复核）；
- critic 轮次均值 ≤ 1.6（过高说明 L2 证据不足或 L3 模板不匹配）。

## L4 分镜 / 版式与视觉：解决"视频只有图片切换"

L4 是形态分支点：视频走 `shot_list`（时间线），图文走 `card_spec` / `layout_spec`（版式）。

### 4.1 根本替换：从"图片序列"到"带图层的时间线"

幻灯片的思维是 `[图1, 图2, 图3] + 字幕`。正确的数据模型是：

```json
{"shot_id": "s07", "start": 18.40, "dur": 3.20,
 "layers": [
   {"type": "bg",      "src": "gradient|image|video", "motion": {"kind": "slow_zoom", "from": 1.00, "to": 1.06}},
   {"type": "subject", "src": "gen_image|broll|screen_rec|chart", "motion": {"kind": "pan", "dir": "left", "px": 40}},
   {"type": "graphic", "src": "chart_bar|callout|arrow|icon", "anim": "grow_in", "params": {"value": 0.83}},
   {"type": "caption", "text": "…", "style": "highlight_word", "words_ts": [1.20, 1.60, 2.00]},
   {"type": "brand",   "src": "logo_watermark", "pos": "tl"}
 ],
 "transition_in": {"kind": "whip_pan|cross_dissolve|mask_wipe", "dur": 0.25},
 "sfx": ["whoosh"], "beat": "on_bar_3", "visual_event": ["zoom", "graphic_in"]}
```

有了这个模型，"是不是幻灯片"变成**可计算、可拒绝**的指标（见 4.3）。

### 4.2 生成策略（脚本 → 分镜）

1. 把每节拆成 3–8 个镜头，每个镜头承载**一个论点或一个转折**，而不是一句字幕；
2. 为每个镜头选择"视觉语法"：`概念隐喻 / 数据可视化 / 对比 / 流程 / 真实感 b-roll / 屏幕录制 / 人物 / 文字排版`；
3. 分配时长：**由音频反推**（TTS 词级时间戳），不是先定时长再凑字；
4. 节奏编排：每 2.5–4 秒一个视觉事件；每 20–30 秒一个节奏峰值（转场/高光镜头）；
5. 风格一致性：所有生成图像带同一 style token + 同一 LUT + 固定 seed 策略。

### 4.3 反幻灯片的量化规则（写进渲染器与 QA，不靠感觉）

| 规则 | 阈值 |
|---|---|
| 视觉事件密度 | 每 2.5–4 秒 ≥ 1 次（切换/运动/元素出现/缩放/色变） |
| 同时运动层数 | 任意时刻 ≥ 2 层有运动 |
| 最长静态连续 | ≤ 4 秒（硬红线） |
| 景别/构图轮换 | 同一景别连续 ≤ 2 次；单条 ≥ 4 种景别 |
| 镜头数 | 短视频 ≥ 1 个/4 秒；长视频 ≥ 1 个/6 秒 |
| 高光镜头 | 全片 3–5 个（生成片段/实拍/复杂动效） |
| 数字呈现 | 一律走数据驱动图表组件，禁止贴截图 |
| 剪点对齐 | 场景切换落在 BGM 小节/8 分音符线上（容差 ±80ms） |

### 4.4 素材获取决策树（按成本/可控性排序）

```
需要画面
├─ 讲数字/占比/趋势？ → 程序化图表组件（最可控、最便宜）
├─ 讲原理/流程/关系？ → 图形动效（节点图/流程/箭头/分层）
├─ 讲概念/情绪/隐喻？ → 文生图 → 图生视频（3–5s 片段，固定 seed + 参考图）
├─ 讲"怎么做"？      → 屏幕录制（自动脚本录制网页/软件）
├─ 需要真实场景？    → 素材库 b-roll（授权库）
└─ 需要人？          → 数字人 / 无脸（手部、背影、空镜）→ 建议默认无脸
```

### 4.5 图文形态：`card_spec` / `layout_spec`

- 卡片组（carousel）：每张卡 = `{layout_id, title, body?, visual{type:chart|image|diagram|text}, emphasis, footer}`；
  版式模板固定 6–8 套（封面/观点/数据/对比/步骤/引述/结尾 CTA），系统只能选模板 + 填内容；
- 长文：`layout_spec` 决定段落节奏与配图插入点（每 300–400 字一张图/一张表），保证"不是纯文字墙"。
- 一致性规则同视频：同一 style token、同一字阶、同一图标集。

### 4.6 音频设计（视频形态，必须先于画面定稿）

| 元素 | 规格 |
|---|---|
| 配音 | TTS，词级时间戳；语速 4.2–4.8 字/秒；每段留 120–200ms 呼吸 |
| 字幕 | 由 TTS 词级时间戳直接生成（不做 ASR 二次对齐），卡拉 OK 高亮 |
| BGM | 按情绪与 BPM 选库；响度 -18~-20 LUFS，人声段自动 ducking（-6dB） |
| 音效 | whoosh/click/riser 卡剪点，密度 ≤ 1 次/6 秒，避免廉价感 |
| 成片响度 | -14 LUFS（平台归一化目标），真峰值 ≤ -1 dBTP |

### 关键参数
| 参数 | 默认 |
|---|---|
| `visual_event_min_gap` / `max_gap` | 2.5s / 4.0s |
| `max_static_run` | 4.0s |
| `shots_per_minute` | 15–22（短视频） |
| `gen_video_clip_quota` | ≤ 20% 镜头数（成本护栏） |
| `tts_rate_chars_per_sec` | 4.5 |

### 失败模式
- 用"一句字幕 = 一个镜头" → 必然幻灯片；
- 先定画面再配音 → 音画对不上，返工；
- 生成式片段比例过高 → 一致性差、成本爆炸；
- 版式模板随意扩展 → 品牌视觉漂移。

### 本层验收
- 全部反幻灯片规则在渲染前静态检查通过（tool 可预演）；
- 每镜头有 `visual_intent` 字段，能回答"这个镜头在讲什么"；
- 图像/片段风格指纹与 style token 距离在阈值内。

## L5 渲染与合成：两条路线，程序化为主干

### 职责
把 `shot_list` / `card_spec` 变成成片、成图与发布素材，并保证可缓存、可局部重渲、成本可控。

### 路线 A（主干）：程序化组件化合成
- 视频：**Remotion（React/TS）**；数学/原理类可用 **manim**；轻量动效可 **Motion Canvas / Vue+GSAP**；
- 图文：**HTML/CSS 模板 → 无头浏览器（Playwright/Chrome）→ PNG/PDF/长图**；
- 字幕、图表、序号、进度条、下三分之一、转场全是**组件**，靠参数变化 → 天然不是"图片切换"；
- 优势：版本可控、一次内容批量换皮（竖/横、30s/60s）、A/B 变体近零成本、渲染可并行、改字只重渲受影响 composition。

### 路线 B（点缀）：生成片段 + FFmpeg 合成
- AI 视频片段 / b-roll / 程序化图形 → FFmpeg concat、转场、调色、混音；
- 用途：真实感与节奏峰值；比例受 `gen_video_clip_quota` 限制。

### 工程要点（最容易被低估）
1. **音频先行**：TTS 时间戳 → 镜头时长 → 字幕 → 画面。（反序必然返工）
2. **响度与混音**：目标 -14 LUFS，sidechain ducking，SFX 卡点，真峰值 ≤ -1 dBTP。
3. **分镜级缓存**：`key = sha256(shot_json + assets_version + style_version + renderer_version)`；未变化的镜头不重渲，最终 concat。
4. **渲染队列分池**：CPU（Remotion）、GPU（图像/视频生成）、TTS 三条独立队列，各自限流与优先级。
5. **成本与时长护栏**：单条作品设 `max_cost`、`max_wall_time`，超限自动降级（减少生成片段、退回图形组件）。
6. **幂等与版本**：产物命名 `run_id/artifact_id/attempt`，任何阶段可重入；同一输入重复渲染结果一致。
7. **字体与依赖锁定**：容器内固定字体集与版本，避免渲染环境漂移导致排版跑版。

### 关键参数
| 参数 | 默认 |
|---|---|
| `render_concurrency` | CPU 4 / GPU 2 |
| `shot_cache_enabled` | true |
| `max_wall_time_per_video` | 12 min（短视频）/ 40 min（长视频） |
| `max_cost_per_video` | ¥15 / ¥60（可配置，触发降级） |
| `loudness_target` | -14 LUFS |

### 失败模式
- 单脚本从头跑到尾 → 一次失败全量重跑，成本爆炸；
- 不锁字体/依赖 → 线上排版和预览不一致；
- 无缓存 → 改一个字重渲全片，不敢迭代。

### 本层验收
- 同一 `shot_list` 两次渲染产物哈希一致（除时间戳元数据）；
- 单镜头改动只触发该镜头重渲（日志可证）；
- 成片技术规格符合平台（分辨率/码率/响度/时长）。

## L6 质检：全自动能不能成立，全看这一层

> **没有自动验收的"全自动"，只是"全自动产出垃圾"**，而且系统不知道自己垃圾。

### 职责
用机器判定"能不能发"，并把不合格项**定向**打回对应层。

### 输入
全链路产物（`script` / `shot_list` / 媒体文件 / `fact_sheet`）+ 阈值配置。

### 输出
`qa_report`：五组检查的逐项结果、总分、`route_back`（回哪一层、带什么 diff）、`decision`（pass / retry / discard）。

### 五组检查（全部可机器判定）

| 组 | 检查项（示例） | 判定方式 |
|---|---|---|
| 1 结构 | JSON schema、字段完整性、时长/字数预算、章节完整性 | schema 校验 + 计数 |
| 2 事实 | 断言是否都在 fact sheet；数字是否与来源一致；`assertable=false` 是否被当事实写；来源是否失效 | 断言抽取 + 比对 + 链接存活检测 |
| 3 合规与平台 | 敏感词/绝对化用语/医疗金融教育断言；标题党程度；AI 生成标识；版权素材指纹；肖像与商标 | 词表 + 规则 + 指纹库 + 模型二审 |
| 4 视频/图文技术 | 黑帧、静音段、字幕出框与遮挡、音画偏差 <80ms、分辨率/码率/响度、首帧吸引力 | FFmpeg/图像分析 + 视觉模型 |
| 5 视觉丰富度（专拦幻灯片） | 视觉事件密度、平均运动幅度、镜头数/分钟、景别多样性、最长静态连续 ≤4s | 帧差/光流 + shot_list 静态校验（双保险） |

### 评分与决策
- 每组内逐项 pass/fail；**关键项（critical）一票否决**（合规、音画偏差、黑帧、AI 标识缺失、无源断言）；
- 非关键项按权重汇总 `quality_score`（0–100），阈值 `≥ 80` 放行；
- 决策：`pass` / `retry(route_back, diff)` / `discard`（记录用于调阈值）；
- **bounded retry**：同类问题最多 3 次；超限升级人工或自动弃稿（弃稿必须留档）。

### 定向回流规则
| 问题类型 | 回退目标 | 回退时携带 |
|---|---|---|
| 事实/来源问题 | L2 | 缺失 claim 列表 + 需要的查询 |
| 结构/逻辑/信息密度 | L3 | 逐段 critic 意见 |
| 画面单调/节奏/一致性 | L4 | 违规时间码 + 建议视觉语法 |
| 技术（黑帧/静音/对齐/响度） | L5 | 具体时间码与修复建议 |
| 选题根本性问题（连续两次 L2 不达标） | L1 | 失败原因，换角度 |

### 失败模式
- 只有"生成"，没有验收 → 垃圾外流且无感知；
- 阈值写死不可调 → 要么全弃稿，要么全放行；
- 检查项不可判定（"是否有趣"）→ 无法自动化，必须换成可测量代理指标。

### 本层验收
- 五组检查全部有可执行判定与阈值版本号；
- 每次 retry 能回答"回哪一层、改了什么、分数提升多少"；
- 发布前 100% 有 `qa_report`，且与发布记录一一对应。

## L7 分发与反馈：系统唯一的进化路径

### 职责
一稿多版、按平台规范发布（或生成发布包）、回采数据并驱动上游优化。

### 输入
`qa_report`(pass) + 成片/成图 + `script` 元信息 + 平台规范库。

### 输出
`publish_package[]`（按平台）+ `feedback_record[]`。

### 处理策略
1. **多版本派生**：竖/横、时长裁剪（60/30/15s）、封面 3 选 1、标题 A/B、首帧不同；
   派生是 L4 参数的重新渲染（有缓存，成本低），不是手工剪辑。
2. **平台适配**：分辨率/时长/封面尺寸/标题字数/话题标签/发布时段/首评话术，全部走平台规范配置，不写死在代码里。
3. **发布模式**：`auto_api` / `semi_auto`（生成发布包 + 人工一键）/ `manual`；默认 `semi_auto`，跑稳后再开 `auto_api`。
4. **回采**：3s 留存、5s 留存、完播率曲线、流失时间点、互动率、涨粉、评论语义（高频提问 = 下一条选题）。
5. **反哺**：
   - 流失点 → L4 该时段的视觉事件密度/镜头长度/信息密度参数；
   - 高完播选题特征 → L1 矩阵权重（bandit / 加权采样）；
   - 高互动句式 → L0 钩子库候选；
   - 平台限流/审核驳回 → L6 规则库。

### 关键参数
| 参数 | 默认 |
|---|---|
| `publish_mode` | semi_auto |
| `feedback_pull_window` | T+1h / T+24h / T+72h / T+7d |
| `bandit_alpha` | 0.3（探索比例） |

### 失败模式
- 只优化生成、不回采数据 → 水平永久停在第一天；
- 一稿只发一个平台 → 单位研究成本产出低；
- 全自动发布无兜底 → 一次违规影响账号权重。

### 本层验收
- 每个作品有完整 `publish_package` 与平台 ID 映射；
- T+24h 数据回采成功率 ≥ 95%；
- 每月至少一次基于数据的参数调整（有记录）。
