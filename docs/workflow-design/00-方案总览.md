# 全自动图文 / 视频生产工作流 —— 完整设计方案（总览）

> **文档状态**：设计定稿候选（v1.0），**只做设计，不含实现**。本套文档不包含任何生产代码，
> 仅定义架构、数据契约、闸门规则、指标、成本与交付路线。
> **输入来源**：用户 2026-11-01 飞书反馈「想要全自动生产图文/视频作品的 AI 工作流」，并提出三个具体不满：
> ① 思路展不开 ② 内容不够 ③ 生成的视频只有图片切换；随后明确「先把完整方案设计好再落地」。
> **与上一版骨架的关系**：上一版给出了 7 层流水线 + 3 道闸门的骨架。本版把它补成**可评审、可估工、可验收**的完整设计：
> 新增内容形态矩阵、逐层输入输出与算法策略、全部 JSON 数据契约、闸门判定条件与人工 SLA、
> 模型路由与提示词规范、成本模型、质量评估体系、可观测性与合规、分阶段交付与验收标准。

## 1. 问题诊断：三个症状都是"缺层"，不是"提示词不好"

| 症状 | 真实原因 | 缺失的层 / 机制 |
|---|---|---|
| 思路展不开 | 单次采样只返回一个"众数答案"；发散与收敛挤在同一个 prompt 里互相压制；没有外部信息注入，模型只能复述训练分布 | 发散层：多路独立采样 + 约束变异 + 红队去陈词 + 聚类去重 + 评分收敛 |
| 内容不够 | 没有检索取证层，"深度"靠形容词而不是靠事实与张力；没有信息密度契约，模型自然写正确的废话 | 研究取证层 + 带硬约束的结构与写作层 |
| 视频只有图片切换 | 心智模型是"帧序列拼接"，没有 timeline / 图层 / 镜头语言，也没有程序化图形能力 | 分镜层（shot list）+ 组件化渲染层 + 可量化的"反幻灯片"指标 |

一句话结论：**全自动 = 一组窄职责的模型各干一件事 + 全程结构化中间产物 + 机器可判定的验收闸门**，
而不是"让一个大模型一口气做完"。

## 2. 目标、非目标与成功度量

### 2.1 目标（本期设计要支撑的能力）

1. 每天无人值守地稳定产出 **图文（长文 / 卡片组）** 与 **视频（60–90s 竖版 / 5–12min 横版）**；
2. 单条作品的人工投入 **≤ 5 分钟**（只为闸门点击，不做编辑）；
3. 内容质量可解释：每条断言可回溯到来源，每个画面可回溯到分镜条目；
4. 系统可迭代：改一处只重跑受影响的环节；换模型/换渲染器不推翻流程；
5. 越跑越好：真实平台数据回灌，驱动选题权重与节奏参数。

### 2.2 非目标（本期明确不做）

- 不做实时 / 直播类内容；不做需要真人出镜拍摄的内容；
- 不做通用剪辑软件替代品（不追求任意素材自由剪辑）；
- 不在本期做多语言本地化（预留字段，不实现）；
- 不追求"一条 prompt 出片"的捷径，也不做纯人工辅助工具。

### 2.3 度量（上线即可测量，避免"感觉变好了"）

| 层级 | 指标 | 定义 | 目标（首季度） |
|---|---|---|---|
| 北极星 | 单条合格作品全成本 | (模型+渲染+素材摊销) ÷ 通过闸门③的条数 | 短视频 ≤ ¥15 / 长视频 ≤ ¥60 / 图文 ≤ ¥3（估算基线，见 04 成本模型） |
| 效率 | 人工分钟/条 | 闸门操作 + 异常处理耗时 | ≤ 5 min |
| 效率 | 一次通过率 FPR | 首次 QA 即全绿的批次占比 | ≥ 70% |
| 质量 | 可溯源断言率 | 成稿断言能命中 fact sheet 的比例 | ≥ 98% |
| 质量 | 每 100 字可断言事实数 | 密度指标 | ≥ 1.2（长文）/ ≥ 2.0（口播稿） |
| 质量 | 视觉事件密度 | 每分钟视觉事件数 | 18–30（短视频）；静态连续 ≤ 4s |
| 效果 | 3s 留存 / 完播率 | 平台回采 | 相对人工基线 ≥ +10% |
| 护栏 | 合规命中率 | 敏感/侵权/未标识问题条数 | 0 |
| 护栏 | 弃稿率 | QA 三次不过被弃 | ≤ 10% |

> 指标的可执行定义、公式与采集口径全部在 **03-闸门与质量体系**。

## 3. 内容形态矩阵（本版新增的关键维度）

"全自动生产图文/视频"不是一条流水线，而是**一条主干 + 四个形态分支**。形态决定哪些层必跑、哪些层换实现。

| 形态 `content_type` | 典型产物 | 必经层 | 分支实现 |
|---|---|---|---|
| `longform_article` 图文长文 | 公众号/知乎 1500–3000 字 + 6–10 图 | L1–L3、L6、L7（无分镜/渲染，改"排版"） | HTML 模板 → 无头浏览器出长图/PDF 与配图 |
| `carousel` 图文卡片组 | 小红书 6–12 张 1080×1440 卡 | L1–L3、L4(卡片版式)、L6、L7 | 卡片 spec JSON → 模板渲染 PNG |
| `short_video` 竖版短视频 | 60–90s，9:16 | L1–L7 全跑 | Remotion 组件合成 + TTS 驱动对齐 |
| `explainer_video` 横版讲解 | 5–12min，16:9 | L1–L7 全跑 + 章节化 | 同上，加章节导航/目录卡/长结构 QA |

同一 `idea` 可派生多个形态（"一鱼多吃"）：主形态定稿后，L4 的 shot list/卡片版式可**降采样**成其他形态，
这是自动化真正的杠杆——一次研究投入，多平台分发。

## 4. 总体架构

### 4.1 分层图

```
              ┌──────────────────────────── 反馈闭环（留存/完播/互动/流失点） ───────────────────────────┐
              ▼                                                                                        │
[L0 资产与基建]                                                                                        │
     │                                                                                                 │
     ├─→ [L1 选题发散与收敛] ──闸门①选题批准──→ [L2 研究取证] → [L3 大纲与脚本] ──闸门②脚本批准──┐      │
     │                                                                                          │      │
     │                                    ┌───────────────────────────────────────────────────┘      │
     │                                    ▼                                                          │
     │                          [L4 分镜/版式与视觉] → [L5 渲染合成] → [L6 质检] ──闸门③发布批准──→ [L7 分发] ─┘
     │                                                     ▲                │
     └────────────────────── 资产回流（钩子库/风格/素材/失效来源）──────────┴── 定向回流重跑（最多3次）
```

### 4.2 控制面 / 数据面（决定这套系统能不能"运维"，而不只是"能跑"）

| 平面 | 组件 | 职责 |
|---|---|---|
| 控制面 | 编排器（状态机） | 阶段调度、重试、超时、预算熔断、闸门等待、回流路由 |
| 控制面 | 闸门服务 | 生成审批卡片（飞书互动卡片）、收集决定、写审计 |
| 控制面 | 预算与配额 | 每 run 成本上限、每模型 QPS、每日总预算 |
| 数据面 | 产物仓库（对象存储） | 所有中间产物按内容哈希存储，不可变、可 diff |
| 数据面 | 元数据库（Postgres） | run / stage / artifact 索引、指标、成本账 |
| 数据面 | 渲染队列（CPU/GPU 分池） | Remotion 渲染、图像生成、视频生成、TTS |
| 数据面 | 模型网关 | 统一鉴权、路由、重试、降级、缓存、计费打点、trace |

### 4.3 各层职责一览

| 层 | 一句话职责 | 关键产出 | 失败时的影响面 |
|---|---|---|---|
| L0 | 提供差异化资产与工程底座（风格、钩子、素材、事实源、网关、编排） | 配置与库 | 全局上限 |
| L1 | 把"选题"变成可评分的候选集 | `idea_batch` | 一切下游都平庸 |
| L2 | 把想法变成可引用的证据 | `fact_sheet` | 内容薄、幻觉多 |
| L3 | 把证据变成有张力的结构与稿件 | `outline` / `script` | 完播率塌 |
| L4 | 把稿件变成镜头/版式时间线 | `shot_list` / `card_spec` | 幻灯片感 |
| L5 | 把时间线渲染成成片/成图 | `render_manifest` + 媒体 | 成本与返工 |
| L6 | 用机器判定"能不能发" | `qa_report` | 全自动变成全自动产出垃圾 |
| L7 | 多平台适配、发布、数据回采 | `publish_package` / `feedback` | 系统无法进化 |

## 5. 五条架构原则（评审时的判断标准）

1. **中间产物一律结构化（JSON Schema），不是自然语言段落。**
   可校验、可 diff、可缓存、可局部重跑、可换渲染器、可做 A/B。
2. **每层都有机器可判定的验收条件。** 不写"要写得好"，写"每节 ≥1 个可溯源数字 + ≥1 个案例 + ≥1 个反直觉点"。
3. **幂等 + 内容寻址缓存。** 所有产物以 `sha256(canonical(inputs) + producer_version)` 为键；
   改一个字只重渲受影响的镜头。这是成本可控与"敢改"的前提。
4. **人只出现在"方向错了会很贵"的地方。** 用预算 + 三道闸门替代逐步审核；
   闸门本身也要有 SLA 与超时策略，否则"全自动"卡在等人。
5. **反馈闭环是一等公民。** 没有真实数据回灌的系统，水平永远停在第一天。

## 6. 关键设计决策（摘要，详见 04）

| 编号 | 决策 | 选择 | 理由 | 代价 / 缓解 |
|---|---|---|---|---|
| ADR-01 | 视频渲染路线 | **程序化组件合成（Remotion）为主干**，生成式片段为点缀 | 可控、可缓存、可批量换皮、天然不是"图片切换" | 需要前端工程能力；用组件库摊薄 |
| ADR-02 | 中间产物形态 | JSON + JSON Schema 严格校验 | 机器可判定、可 diff、可重算 | 前期 schema 设计成本高 |
| ADR-03 | 编排实现 | 持久化工作流引擎（Temporal 优先） | 长任务、可重入、可人工等待、可观测 | 运维一个额外服务 |
| ADR-04 | 人工介入 | 三闸门 + 飞书互动卡片 | 与现有 IM 工作流贴合，零额外客户端 | 卡片交互能力需验证 |
| ADR-05 | 图文渲染 | HTML/CSS 模板 + 无头浏览器 | 排版能力强、模板易改、与视频共用设计 token | 需字体/渲染一致性治理 |
| ADR-06 | 音频先行 | TTS 词级时间戳驱动镜头时长与字幕 | 音画对齐是自动化的生死线 | 依赖 TTS 时间戳质量 |
| ADR-07 | 模型策略 | 分层路由：贵模型做创意与评审，便宜模型做批量改写与打标 | 成本与质量平衡 | 需要评测体系支撑换模型 |

## 7. 质量闭环（系统唯一的"进化"路径）

```
发布 → 回采（3s留存/完播曲线/流失时间点/互动/涨粉）
   ├─ 流失点 → L4：该时刻视觉事件密度、镜头时长、信息密度是否不足
   ├─ 高完播选题特征 → L1：选题矩阵权重（bandit 加权采样）
   ├─ 高互动段落/句式 → L0 钩子库
   └─ QA 误判样本 → L6 阈值与规则回归集
```

没有这一层，系统只是"更快地产出同样平庸的内容"。

## 8. 交付路线（摘要，详见 05）

| 阶段 | 周期 | 范围 | 验收标准（可判定） |
|---|---|---|---|
| P0 设计定稿 | 3–5 天 | 本套文档评审、指标与 schema 冻结 | 本文档 + 02/03 通过评审，待决策项关闭 |
| P1 图文先行 | 1–2 周 | L0–L3 + 图文排版 + 文本 QA + 人工发布 | 连续 5 天日更 3 篇，FPR ≥ 60%，人工 ≤ 5 min/篇 |
| P2 短视频 | 2–3 周 | shot list + Remotion 组件库（10 组件）+ TTS 对齐 + 视频 QA | 30 条成片，静态连续 ≤ 4s 合规率 100%，视觉事件密度达标 |
| P3 无人值守 | 2 周 | 闸门自动化、多平台适配、数据回采、预算熔断 | 7 天无人干预运行，仅闸门点击；成本在预算内±20% |
| P4 复利 | 持续 | 生成式片段、风格一致性、A/B 规模化、bandit | 相对 P3 基线，完播率 +15%，单条成本 −20% |

**顺序不可颠倒**：先用图文验证"内容质量能靠架构提上来"，再投入渲染工程。
反过来会陷进"做特效"，而内容依旧平庸。

## 10. 风险登记（Top 6）

| 风险 | 影响 | 概率 | 缓解 |
|---|---|---|---|
| 平台对 AI 生成内容限流/限权 | 分发受阻 | 中 | L6 强制 AI 标识、原创度检查、多平台分散、保留人工发布兜底 |
| 素材版权（BGM/图片/视频片段） | 下架/索赔 | 中 | L0 版权登记表 + 指纹校验，只用可商用库与自产素材 |
| 模型/供应商价格或能力突变 | 成本与质量波动 | 高 | 模型网关抽象 + 每阶段双供应商 + 评测集快速换模 |
| 自动 QA 阈值过严/过松 | 弃稿率高或垃圾外流 | 高 | 阈值版本化 + 抽检人工标注回流 + 回归集 |
| 一致性差（同一账号风格漂移） | 品牌受损 | 中 | style token 参数化 + 参考图/固定 seed + 出片前风格指纹比对 |
| 一次追求全自动 | 上线即失控 | 中 | 三闸门渐进自动化，P2 前必须有人审 |

## 11. 需要你先拍板的 10 个问题（决定后续实现细节）

1. **首发平台与形态**：先做哪个？（建议：小红书/公众号图文 + 抖音/视频号竖版短视频）
2. **账号定位与题材边界**：知识科普 / 商业观察 / 工具测评 / 其他？是否有不能碰的行业（医疗、金融、教育）？
3. **品牌视觉**：是否已有 VI（色板/字体/logo）？没有则需在 P1 前定 1 套 style token。
4. **配音**：是否接受 AI 配音？是否需要真人声纹克隆（涉及授权）？
5. **出镜**：是否接受数字人？或采用"无脸"方案（手部/空镜/图文动效，最省事最稳）？
6. **发布方式**：全自动 API 发布，还是"生成发布包 + 你一键发"？（建议 P4 前保持半自动）
7. **每日产能与预算**：每天几条？单条成本上限多少？决定并发与模型档位。
8. **合规态度**：是否按国内平台要求做显式 AI 生成标识？（建议做，成本极低）
9. **数据回采权限**：平台后台数据是否可导出/授权读取？决定 L7 闭环能做到多细。
10. **既有资产**：有没有历史文稿/素材库/爆款样本可作为 L0 冷启动语料？
