# 内容生产工作台 · 项目开发方案总览 v0.7

> 汇总时点：2026-11-02 16:24。**v0.7 变更**（本轮 3 条答复）：① **网络检索由工作流自己承担**，并划清它与另一套系统的边界（§2.4）；② **引用对账确认保留**（§6.2）；③ **允许在成稿中点名提到他人**，配套三条红线（§6.3）。  
> **v0.6 变更**（上一轮）：吸收你在飞书文档 v0.5 上的 4 处修改；取消"重复事实核验"；平台数量改为可扩展；"自主立项"改为排期靠后而非永久否决。  
> 不含任何生产代码。本文只定义：范围、架构、契约、闸门、质量、成本、节点、风险、未决。

## 一、做什么 / 不做什么

### 1.1 做

**一个话题进来 → 三个平台出去**：未来不一定只有三个平台，可以留接口预备以后接入其他平台。

| 平台 | 形态 | 规格 |
|-|-|-|
| 公众号 | 长文 | 1500–3000 字 + 6–10 图 |
| 小红书 | 卡片组 | 6–12 张 1080×1440 + 正文 ≤1000 字 + 标题 ≤20 字 |
| 抖音 | 竖屏视频 | 60–90 秒，9:16，真分镜 + 配音 + 动效 |

一条完整的链：**出题 → 你批 → 仓库取材 → 网络参考采集 → 引用对账 → 成稿 → 你批 → 版式渲染 → 质检 → 你批 → 三平台发布 → 回读核实 → 数据回采**。全程你只点三次（每道闸门），其余我兜。

### 1.2 不做（明确划掉，避免后期扯皮）

- 数字人、声纹克隆（契约留字段，不实现）
- 多语言本地化
- 通用编辑器替代品（**不改稿、不精修**，你只做闸门决策）
- **重复的事实核验**（v0.6 改：料在入库时你已核验，管线不再重做一遍，见 §6.2）
- 外部信号监听与自主立项（**初版不做，以后版本实现**）
- **热点/主题发现式检索**（那是另一套系统的事；我们只做"已经定题之后、围绕这道题"的采信检索，见 §2.4）
- 搬运：参考内容不二次分发、不进成片像素

## 二、料从哪来、谁定题

### 2.1 事实料的唯一来源：Obsidian 仓库

- 部署：虚拟局域网内一台设备，装 Obsidian **Local REST API** 插件，开端口
- 访问：只读凭据，不出公网，本地 sqlite 增量索引（按文件哈希，不整库重扫）
- 素材入库存一张**三格小卡**：`出处` / `授权` / `标签`，10 秒填完
- **入库即视为已核验**（你的判断）：出处在入库时已确认，管线不再重建事实清单
- 但仍有一条**硬底线**：`出处`与`授权`不许我自动补（模型会编一个看起来很像的链接）。没写出处的素材可当灵感与观点用，**不得进正文的事实断言**
- 参考视频**不进成片**：只抽参数（钩子/节奏/结构/动效）落成风格模板，供版式与渲染读

### 2.2 选题权归你，三个入口，没有第四个

1. **你给题** → 直接开工
2. **你给个模糊想法** → 我先问清关键点（用户画像、内容匹配等），**问清楚之后**再出候选
3. **你要推荐** → 走推荐引擎，出 3–8 个候选、预勾选 1–3 个、你批红

**初版不主动立项、不定时出题**。仓库里料再多也不会自己开跑。事件层退化为索引层（新素材入库只建索引，不触发动作）。**主动推荐/自主立项放在以后版本实现**——所以这条不是永久否决，是排期靠后。

### 2.3 推荐引擎：三只脚同时站住才推

| 脚 | 内容 |
|-|-|
| 已发内容台账 | 近 90 天发过什么，避免重复，或做续集/反差 |
| 数据表现 | 哪类角度真有效（完读/收藏/涨粉）；数据不足就明写"数据不足"并降权，不假装有依据 |
| 仓库素材可用性 | 必须能点名"用哪几条素材支撑" |

硬规则：**点不出具体料的候选不许出**；料不够就直说"现在只能撑起 X 个方向，建议先补料"，不硬凑。

### 2.4 检索由工作流自己做，但边界要划死

**已定**：围绕已选题目的网络参考采集，由本工作流自带检索能力完成（不等另一套系统回灌）。

边界对照表（防止两套系统重复建设）：

| 事 | 谁做 | 触发时机 |
|-|-|-|
| 发现"现在什么值得做"（热点、榜单、竞品动向、评论挖需求） | **另一套系统** | 持续巡检 |
| 已定题之后"这道题别人怎么讲、怎么用、争议在哪" | **本工作流** | 只在闸门①通过之后按需触发 |
| 为已发内容做数据回采与复盘 | 本工作流 | 发布后按周期 |

实现要点：

- 通道：搜索接口 + 正文抽取 + 限速与退避重试；
- **快照存证（必须）**：每条参考都要留 `抓取时间 / HTTP 状态 / 正文哈希 / 关键段落摘录`。网页会改版、会消失，不留存证就等于事后无从核对"人家当时到底说了什么"；
- **抓不到就说抓不到**：登录墙、反爬、区域限制导致的失败如实标注 `unavailable`，不用模型补写"大概内容"——这是最容易变成编造的地方。

## 三、架构

### 3.1 分层（L0–L7，保留内部编号但附白话）

| 层 | 白话 | 产出 |
|-|-|-|
| L0 | 资产与底座（风格、钩子库、素材台账、模型网关、编排） | 配置与库 |
| L1 | 出题 | 候选集 |
| L2 | **取材与参考**（v0.6 改：不再做重复核验） | 事实素材集 + 网络参考集（两种身份，见 §6.2） |
| L3 | 写稿 | 母版叙事 + 三形态文案 |
| L4 | 排版/分镜 | 长文 HTML / 卡片版式 / 分镜表 |
| L5 | 渲染 | 长图、PNG、成片 |
| L6 | 质检 | 质检报告 |
| L7 | 发布与回采 | 发布包 + 数据 |

### 3.2 一次研究、中段扇出（多平台的核心形状）

```Plaintext
你给题 → 出题(一次) → ✋批 → 取材(仓库) + 参考(网络) + 对账(机械)
                                   │
        ┌──────────────── 扇出 ────────────────┐
     公众号长文            小红书卡片组          抖音竖屏视频
        └──── 各自：文稿✋ → 版式渲染 → 质检 → 发布✋ → 回读 → 回采 ────┘
```

- 共享：选题、取材结果、参考集、母版叙事
- 分叉：文体、版式渲染、平台规则质检、发布适配
- **母版形态**先定（视频优先为常态），子形态只能删减、不得新增论点
- 平台是列表不是固定三个：新增平台=新增一条分支实现，不动上游

### 3.3 一致性三条硬规则

1. 三条产物引用**同一版本的事实素材集**；素材变更要升版本并触发其他平台"漂移复核"
2. 论点只有一份，母版定，子形态不得加
3. 发布卡上直接显示"三平台关键数字一致性 ✅/⚠️"；价格统一取整口径

### 3.4 失败隔离

一个平台挂了不连坐：各自独立状态、独立预算、独立重试；父状态只报"部分完成"；重跑能细到"只重跑抖音分镜"，不重跑取材；已发布的不受重跑影响。

## 四、你看到的东西：闸门卡片

三道闸门（选题 / 文稿 / 发布），每道一张**票拟式卡**：

- **九个字段**：一句话请示（≤30 字）｜我的建议＋置信度｜为什么（≤3 条带数字）｜关键数字（质量分/成本/限额余量）｜最坏情况＋我为什么不担心｜已做/未做｜最多 2 个备选｜唯一一个请示问题｜页脚（版本/有效期/今日第几张）
- **三个按钮**：同意（零输入）｜拒绝（零输入，默认勾"记入长期偏好"）｜自定义回复（打字，**先回执"我理解你要 X，对吗"确认后才执行**；解析不了就回问，绝不猜）
- **不合并**：每平台各自一张文稿卡 + 一张发布卡（一题 6 张）。视频卡永远单独且最先批（最贵）
- 减噪只靠三件：卡变短、到达时间错开、可选"其余平台按同一母版放行"的临时授权勾
- 自检：**卡片上没有"我的建议"= 我做错了**

## 五、我什么时候停下来找你

**必问九类**：花钱（超上限/开新额度）｜对外发（含回复读者）｜改方向（赛道/定位/体裁配比）｜动数据账号权限｜高风险题材（医疗、理财、教育升学承诺、法律、政企负面）｜**素材与参考冲突、或参考里出现仓库没有的关键事实**｜我没把握｜同一件事第二次失败｜**我没见过的情况（不问就是猜）**

**不问**：常规返工（换图/改排版/统一术语/补图表）、按既定原则的常规执行

**你定过的事不再问第二遍**，但须：① 先贴出你的原话与日期 ② 赛道/体裁/预算/风险级四项未变 ③ 同一类事项。**花钱、对外发、高风险、改方向、动账号权限永远重问**

**不设注意力上限**（项目刚起步，先要信息对称）。审计留全量，每周出一页"我本可自己判断"的复盘。

## 六、内容准备与质量（v0.6 重点重构）

### 6.1 三种料，三种身份，绝不混用

| 类型 | 来源 | 能不能进正文断言 | 用途 |
|-|-|-|-|
| **事实素材** | Obsidian 仓库（入库时你已核验，带出处/授权/标签） | **能** | 论点、数字、结论 |
| **网络参考** | 按素材在公网检索到的：用法与教程、其他平台博主的同类内容、讨论与争议 | **不能** | 角度参照、结构参照、误区与踩坑清单、对比清单 |
| **待核实线索** | 参考里看到、但仓库里没有的说法 | 不能（除非补登记成事实素材） | 提示"这条值得查" |

### 6.2 取消重复核验，改为"参考采集 + 引用对账"

**删掉的**：原来那套"逐条重建事实清单、逐条判来源等级"的重活。理由是你的判断——入库时已核验过，再核一遍是浪费，而且我并没有比你更权威的核验能力。

**新增的（你要的这步）**：按已通过的素材去公网做**参考采集**，采三类——

1. **用法/教程**：这东西怎么用、参数怎么设、真实操作步骤、常见坑；
2. **其他平台博主的同类内容**：他们从什么角度讲、开头怎么起、讲了什么、**漏了什么**；
3. **讨论与争议**：评论区高频疑问、反驳意见、踩坑记录。

产出 `reference_set`（每条带链接、平台、作者、时间、要点、以及"可借鉴/可反驳"标记）。

**保留一道极轻的机械环节：引用对账**（不联网、不搜源、不做事实判断）——只查两件事：

1. 成稿里的每个数字/说法，是否与笔记原文一致（防改写时数字漂移、口径丢失）；
2. 笔记里标为"推测/听说/未确认"的内容，有没有被我写成"数据显示"。

> **已定（16:20 你答"保留"）**：引用对账保留。它不重新核事实，只做机械比对——**核验解决"这料对不对"，对账解决"抄进稿子时有没有抄歪"**，两件事。

### 6.3 三条"不许"（防止参考变证据）

1. 参考内容**不许当断言**：只能作为角度、结构、误区清单的来源；
2. 参考内容**不许进成片像素**、不许二次分发（沿用既有决定）；
3. **升级通道**：参考里某条若确实要当事实讲，必须回到仓库登记成素材卡（出处/授权/标签），登记后才算证据。

### 6.3-bis 点名提到他人的三条红线（16:20 你答"可以"）

允许点名，但只在这三种情形，且都要满足"可点开、可核对、不失真"：

1. **转述观点**（"某博主认为……"）→ 必须附**可点开的链接 + 作者 + 时间**，不得剪裁成我想要的意思；
2. **做对比或举例**（"他讲的是 A，我们这次补的是 B"）→ 同上，且对比要指向具体内容，不指向人；
3. **逐字引用**（超过短语级）→ 强制标注作者与作品名（这是既有的法律红线，不受 `attribution_policy` 开关影响）。

三条不许：

- **不许点名做负面指控**（说某人错、某人恰饭、某人是水文）——商誉与侵权风险都在这里；确有负面必须讲，走"必问"找我，由你决定要不要说、怎么说；
- **不许点名不可核实的对象**（"评论区有个人说""群里有人讲"）——没有链接就没有点名资格，只能写成"有读者反馈"这类无指向表述；
- **仍不许用他人画面/截图进成片像素**（沿用既有决定，除非单独授权）。

### 6.4 参考集顺带解决的另一个老问题

"去 AI 味 / 反陈词"以前靠模型自己想象"什么是套话"，现在可以靠参考集落地：**把别人都在说的那 5 句话提取出来，然后成稿不写**。这是我们差异化的实质来源，且可复核。

### 6.5 质检两层

| 层 | 项 | 是否拦发布 |
|-|-|-|
| 硬错层 | 引用对账、合规（AI 标识/授权/平台限额）、结构完整、**音画同步**（视频分支） | **拦** |
| 风格层 | 去陈词、AI 味、套话密度 | **不拦**，只进质量分与日报 |

审查角色硬约束：只读、不改稿、不联网、不拿发布凭据；同一稿最多三轮，三轮不过弃稿。

### 6.6 合规（延续既有决定）

- AI 生成标识：走**平台发布声明的开关**，每次必须主动声明；导出链路**禁止剥离元数据**
- 出处标注：对外默认不标（`minimal`），但内部溯源不放松；**逐字引用他人文字/图表强制标注**
- 热门案例与网络参考：只作参考，不进成稿像素、不二次分发

## 九、风险（按严重度排序）

| # | 风险 | 为什么严重 | 应对 |
|-|-|-|-|
| 1 | **首期就上视频＝把最难的一层放进第一步** | 渲染/动效/音画对齐最易翻车，是你最初的三大不满之一 | N4 样片风险闸，不过关不铺并发 |
| 2 | **参考被当成事实用**（v0.6 新增风险） | 参考集没经过核验，一旦混入断言，等于把"别人说的"当"事实"发出去 | 三条"不许" + 升级通道 + 对账检查参考条目是否越界 |
| 3 | **站内内容抓不到**（v0.6 新增） | 抖音/小红书站内有登录墙与反爬，"其他博主的内容"大概率只能拿到公网页（公众号/知乎/B站/官网） | 预期先说明；抓不到就只做公网部分，不假装有 |
| 4 | 抖音发布无 API | 个人号大概率无法自动发布，工期承诺会落空 | N1 核实；若无则走打包一键发（与小红书同路） |
| 5 | 仓库无元数据 → 素材可用性索引弱 | 推荐准确率打折，容易出现"推了但没料" | 新素材三格小卡从现在积累；推荐时逐条列依据；一个月后看覆盖图 |
| 6 | 平台数量扩张时的接口债 | 你说未来不只三平台 | 平台做成列表 + 适配器接口，分支实现可插拔（架构上已按此设计） |
